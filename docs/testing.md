# Testing and validation

NLPDiagnostics separates software regression tests from scientific calibration.
A passing unit test proves that an implemented contract behaves as specified;
it does not prove that a numerical threshold or physical interpretation is
well calibrated.

## Continuous-integration lanes

The CI workflow has three explicit lanes:

1. **Package** runs the declared package test target on Julia 1.10 and the
   current stable Julia release. This covers the generic core, JuMP, and the
   registered PowerModels boundary.
2. **Solver extensions** creates an isolated environment containing JuMP,
   Ipopt, and MadNLP. It runs the same regression suite with both public
   callback extensions loaded.
3. **Domain extensions** creates an isolated environment containing JuMP,
   Ipopt, PowerModels, and the authoritative BMOPFTools Git repository. It
   exercises the optional physical-metadata and staged OPF adapters.

The lanes are intentionally separate. A missing optional dependency must not
silently make its extension appear tested.

## Local full-extension test

The benchmark bootstrap creates a local environment containing the optional
solver and domain dependencies:

```sh
julia --startup-file=no benchmarks/bootstrap_benchmark_environment.jl
julia --startup-file=no --project=work/benchmark-environment test/runtests.jl
```

The bootstrap modifies only the explicit benchmark environment. It develops
the selected local NLPDiagnostics and BMOPFTools checkouts and should not be
used as the minimal package environment.

## Calibration tests

A calibrated finding family additionally requires the positive case, negative
control, tolerance/scaling sensitivity, unavailable path, and bounded-work
checks listed in [`mission_and_scope.md`](mission_and_scope.md). Benchmark
reports must retain their schema version, environment fingerprint, point
provenance, solver options, and numerical policy.
Environment fingerprints include both the Git revision and, when the checkout
is dirty, a content fingerprint covering tracked differences and untracked
non-ignored files. This makes a development-tree result reproducible without
embedding the source diff in the report. A clean and dirty checkout at the same
commit therefore cannot silently share an environment fingerprint.

Warnings generated by intentionally singular transformer fixtures are expected
test evidence when their associated assertions pass. Unexpected warnings,
native exits, timeouts, and missing artifacts remain failures or explicit
unavailable evidence; they are not suppressed to make a campaign green.

The solver-portability scaling runners are
`benchmarks/bmopf_stratified_scaling_campaign.jl` for Ipopt and
`benchmarks/bmopf_stratified_madnlp_campaign.jl` for MadNLP. Both construct
fresh models, transport identical physical starts, and apply the same endpoint
qualification. Ipopt additionally supports captured-iterate family geometry;
MadNLP instead retains its public cumulative factorization, backsolve,
linear-solver-time, and derivative-evaluation counters. A one-stratum run is
deliberately rejected by the stratified aggregator.
